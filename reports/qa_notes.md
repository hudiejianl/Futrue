# Q&A Notes

## 1. 为什么最终主模型不是多模态？

回答思路：

- 我一开始系统性做了 `Force-only`、`Force+Vibration/Sound`、`Force+Image` 和三模态 baseline
- 结果表明当前数据质量和实现条件下，`Force-only` 最稳定
- 所以我没有为了追求热点强行坚持多模态更强，而是根据实验结果把它收敛成主预测骨干
- 多模态在当前项目中更多承担辅助分析和解释上下文的作用

## 2. LLM 在项目里起什么作用？

回答思路：

- LLM 不直接代替底层感知模型
- 它消费的是结构化预测摘要、规则命中和知识检索结果
- 主要作用是生成更自然、可读、可执行的诊断报告和换刀建议
- 这样更符合工业系统中“预测 + 解释 + 决策支持”的定位

## 3. 知识库和规则引擎是怎么设计的？

回答思路：

- 知识库是结构化 JSON
- 每条条目包含适用条件、风险等级、建议动作、证据类型、标签
- 规则引擎负责做确定性筛选
- 检索器负责基于条件和简单评分选取相关知识项
- 再交给模板模式或 DeepSeek 做最终报告生成

## 4. 为什么还要保留 template 模式？

回答思路：

- template 模式可控、稳定、本地可运行
- DeepSeek 模式更自然、更适合展示
- 两者配合可以同时满足工程可控性和演示效果

## 5. DeepSeek 做了什么验证？

回答思路：

- 我不是只在代码里预留了接口
- 已经用 `deepseek-v4-flash` 做过真实端到端调用
- 并且完成了 `template vs deepseek` 的报告对比
- 结果表明 DeepSeek 的语言质量更好，更适合作为展示模式

## 6. 边缘部署是怎么体现的？

回答思路：

- 主模型已经导出为 ONNX
- 已完成 CPU benchmark
- 有模型大小和平均延迟结果
- 虽然还没有上实际工业板卡，但部署链路和性能验证已经具备

## 7. 项目最大的不足是什么？

回答思路：

- 多模态分支没有稳定形成性能优势
- 振动模态有坏文件
- 图像分支没有预训练
- LLM 层虽然已接入 DeepSeek，但知识库和检索还可以继续扩充

## 8. 如果继续优化，你会先做什么？

回答思路：

优先级是：

1. 扩知识库和案例
2. 继续优化 DeepSeek 提示词和输出质量
3. 打磨 demo
4. 如果再有时间，再提升图像分支和振动特征
