# Interview Script

## 1. 三分钟版本

我的项目是一个面向智能制造场景的刀具磨损监测与解释原型系统，数据使用的是公开的 QIT-CEMC Dataset。整个系统分成三层。

第一层是预测层。我先对原始数据做了清洗和结构化处理，把力/扭矩、振动/声音、图像和磨损标签整理成可训练的样本索引。然后我分别做了 `Force-only`、`Force+Vibration/Sound`、`Force+Image` 和三模态 baseline。实验结果表明，在当前数据质量和工程条件下，`Force-only` 是最稳定、最强的主预测模型，所以我把它固定为主骨干。

第二层是解释层。我没有只停留在输出一个磨损值，而是做了一个规则引擎、知识库检索和大模型报告生成链路。系统会先生成结构化预测摘要，再匹配规则和知识库，最后通过 DeepSeek 的 `deepseek-v4-flash` 生成诊断报告和换刀建议。这样项目就具备了可解释性和交互性。

第三层是部署层。我把主模型导出成 ONNX，并做了 CPU benchmark，验证它具备边缘部署的可行性。同时我还做了一个 Gradio demo，可以展示图像、模型输出、规则命中、知识检索结果和最终报告。

这个项目的核心价值不在于我强行证明多模态一定优于单模态，而在于我比较真实地完成了从数据处理、模型实验、解释模块到部署验证的完整系统原型。

## 2. 八分钟版本

### 2.1 项目背景

我做这个项目的出发点是，工业场景里很多研究只关注预测精度，但真实系统更需要“预测 + 解释 + 部署”。所以我希望做一个更完整的刀具磨损监测原型。

### 2.2 数据处理

数据来自 QIT-CEMC Dataset，里面包含力/扭矩、振动/声音、图像和磨损标签。这个数据集原始格式比较散，标签是 `xls`，不同模态之间还有缺失和损坏样本，所以我先做了数据清洗和索引构建，包括：

- 标签展开
- cycle 对齐
- train/val/test 划分
- 力与振动特征提取

### 2.3 模型实验

在模型上，我没有一开始就做复杂多模态融合，而是先做多组 baseline：

- `Force-only`
- `Force+Vibration/Sound`
- `Force+Image`
- `Force+Vibration/Sound+Image`

实验后我发现，当前数据条件下 `Force-only` 在回归和分类上都最稳，所以我没有强行坚持“多模态必须最强”，而是把它调整成更真实的系统叙事：

- `Force-only` 做主预测
- 其他模态做辅助信息

### 2.4 解释模块

我后面重点补的是解释模块。这里不是简单输出一段固定文本，而是分成：

- 结构化预测摘要
- 规则引擎
- 知识库检索
- DeepSeek 报告生成

现在支持本地模板模式，也支持 `deepseek-v4-flash`。DeepSeek 的作用主要是把模型输出转成更自然、更像工业诊断报告的文字。

### 2.5 部署验证

为了让项目更像真实工程系统，我把主模型导出成 ONNX，并完成了 CPU benchmark。结果表明模型很轻，推理延迟也很低，所以能支撑“端边协同部署”的说法。

### 2.6 项目结论

这个项目最后的价值主要有三点：

1. 做了完整的数据处理和系统链路，而不只是训了一个模型
2. 用解释模块和 DeepSeek 提升了系统的可解释性
3. 做了 ONNX 导出和 demo，让它具备了展示和部署基础

## 3. 常见追问与回答思路

### Q1：为什么多模态没有作为最终主模型？

回答思路：

因为实验结果表明，在当前数据质量和实现条件下，`Force-only` 更稳定。我没有为了追热点硬说多模态更强，而是把多模态定位成辅助分析和解释上下文。这种结论更符合实验事实，也更接近真实工程决策。

### Q2：LLM 在这里真正起了什么作用？

回答思路：

LLM 不是去直接做底层感知预测，而是消费结构化预测摘要和知识库结果，生成更自然的诊断报告和建议。这样它发挥的是“解释与决策支持”的作用，而不是替代预测模型。

### Q3：边缘部署是停留在口头上吗？

回答思路：

不是。我已经把主模型导出成 ONNX，并做了 CPU benchmark。虽然还没有上实际工业板卡，但部署链路和性能验证已经具备。

### Q4：项目还有哪些不足？

回答思路：

当前多模态增益还不稳定，图像分支没有预训练，振动模态有坏文件，LLM 解释层也还可以进一步做更强的检索增强。这些我都整理成了后续改进计划。
